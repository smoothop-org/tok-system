# publications/stokex

Defensive publication of the **$tôkEx** algorithm (`stokex_defensive_publication.tex`),
its figures, its companion scripts, and its formal proofs.

## What the folder contains

| Path | Role |
|---|---|
| `latex_document/stokex_defensive_publication.tex` / `.pdf` | the document — 30 pages, the only piece submitted to TDCommons |
| `figures/gen_figures.py` | generates the 7 PDF figures of the document |
| `figures/*.pdf` | the generated figures: `stokex_symmetry`, `trader_function`, `stokex_steps`, `degree_of_certainty`, `degree_of_certainty_log`, `personal_trading_robot`, `cadeur_example` |
| `figures/cadeur_daily.csv` | FRED data for the CAD/EUR example (`cadeur_example.pdf`) |

## Python environment (local, permanent, **never pushed**)

The figures are generated by `gen_figures.py` (matplotlib + pandas, text rendering
via system LaTeX). The environment lives in a single `.venv/` at the **repo root**
that is **local and gitignored**: it is shared by every instance of Milu on the
machine, but never leaves for GitHub. Only `requirements.txt` — the *recipe*, at the
repo root — is versioned. Never create a second `.venv` (see AGENTS.md).

## Generating the figures

```sh
./.venv/bin/python publications/stokex/figures/gen_figures.py
```

Writes the 7 PDFs into `publications/stokex/figures/` (the script's own directory,
independent of the current working directory). The reference-UI screenshots
(`reference_implementation_ui_*.png`) are **not** produced by the script — they
are added by hand.

## Compiling the document

Simple one-shot build, from the document's directory:

```sh
cd publications/stokex/latex_document
latexmk -pdf -interaction=nonstopmode -halt-on-error stokex_defensive_publication.tex
```

Continuous build — this is the **auto compile** recipe defined in AGENTS.md; it
keeps latexmk running and rebuilds on every save of the `.tex`, with no viewer:

```sh
cd publications/stokex/latex_document
latexmk -pdf -pvc -view=none -interaction=nonstopmode -halt-on-error stokex_defensive_publication.tex
```

It runs until stopped (Ctrl-C). `latexmk` handles the multiple passes
(cross-references, bibliography) on its own. The build artifacts (`.aux`, `.log`,
`.fls`, `.fdb_latexmk`, `.out`, …) are gitignored.

## Verifying

The three verifications, independent of one another:

```sh
./.venv/bin/python publications/stokex/python_toy/verify_stokex.py   # 13 numerical tests
./.venv/bin/python publications/stokex/python_toy/stokex_toy.py      # the toy, with its own checks
cd publications/stokex/lean_proofs && lake build                     # the Lean proofs
```

The Lean setup is **self-contained in this repo** (see AGENTS.md, "Lean"): the
toolchain is pinned by the repo-root `lean-toolchain` (`leanprover/lean4:v4.32.0`),
mathlib is prebuilt in the shared `.lake-shared/` cache (the $tôkEx `lean_proofs.lake`
symlinks to it), and the proofs build on the shared `lean_common/` foundation
(library `TokCommon`), which stokex `require`s by relative path. So a plain
`lake build` from `lean_proofs/` verifies everything — no `lake exe cache get`
needed, the oleans are already local. An error-free build **is** the result: all
the theorems are verified. Run `lake` from the project directory, never from the
bare repo root. See `lean_proofs/README.md` for the exact scope of what is proven.

## Placeholders and go-live

The document uses a `\placeholder{...}` macro (yellow box) to mark what remains to
be filled in before submission. The full go-live checklist (removing the
placeholders, tagging, TDCommons submission, etc.) is in `stokex_go_live.md` — an
internal working file, gitignored: it lives on the machine, not in this repository.

Before tagging/submitting:

```sh
grep -n "À COMPLÉTER\|placeholder" latex_document/stokex_defensive_publication.tex
```

must return nothing in the body of the text (the "placeholder" entries in the
notation table, a mathematical term, are legitimate).

## My opinion on what remains open

**Annex 7.9 is orphaned — this is my main recommendation.** *Behavior of the market
as one participant's weight diverges* is referenced **nowhere** in the body. The
domain $[0,100)\,\%$ appears three times (l. 340, 571, 659) and the 99.9999 % ceiling
once (l. 708), always without saying where the choice is justified. This is the annex
that answers "what if someone declares 100 %?" — the first question an examiner asks,
and it cost a day of work on August 11. Irony of the folder: it is `stokex_toy.py`
(l. 44) that makes the correct cross-reference, not the document. **A handful of words
at l. 708 is enough**: "(see Annex~\ref{secProofInfiniteWeight})".

**The "participant / trading robot" item in `TODO.md` can be closed.** The annexes
still say "a participant's exchange velocities", but the body has laid down the
distinction (§3.1, Fig. 1, principle 3, Alice's example) and a mathematical annex
need not repeat it: it is ordinary metonymy, not a confusion. Weighing down ten
sentences of proof to say "the participant's robot's velocities" would cost more than
it clarifies. My opinion: close the item while noting it, rather than leaving it open
at the tag.

**What I would leave as is today**, flagging it so it is a choice and not an
oversight:

- The bibliography order does not follow the order of appearance: the calls come out
  [4], [5], [2], [3], [6], [7], [1]. Purely cosmetic.
- `\begin{thebibliography}{1}` with 7 entries — the argument sets the label width;
  `{7}` would be right. No visible effect here.
- `smoothblue` = `#0F8EB1` (l. 12) is from the previous generation of the palette
  (`Style.md` says `#0B85A6`). Invisible gap, already tracked in `TODO.md`; fixing it
  would force a recompilation for nothing.
- Seven `% locked` markers and the wink `% uman author, smooth operator` (l. 96)
  remain in the source, which is public forever. Nothing compromising — but it is now
  or never.
- Six `\label` never referenced (including `eqTotalMarketWeight2` and `figDegreeBoth`):
  normal for reference-numbered equations. The name `eqAvergageParticipantDegree`
  carries a typo, invisible to the reader.
- `family_price.png` and `trader_family.png` are versioned while `stokex_toy_sim.png`
  is gitignored on the grounds of "a regenerable illustration, not a specification".
  The two doctrines coexist in the same folder. Low stakes: removing them would not
  clean the history anyway.
